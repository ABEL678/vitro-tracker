# Правила проекта Vitro-tracker (для AI-агента)

## Язык и стиль
- Отвечать на русском языке.
- Пользователь — не программист: объяснять пошагово.
- Давать ПОЛНЫЙ код файлов, не фрагменты.
- Сначала план — потом код. Не писать код без согласования.
- Если правка что-то ломает — предупреждать.
- Тестировать каждый шаг перед следующим.
- Каждое изменение — отдельный коммит в Git.

## Что НЕЛЬЗЯ трогать без явной просьбы
- `vitro/sync.py` — логика синхронизации
- `vitro/sharepoint.py` — загрузка из Витрокад
- `vitro/sqlite_db.py` — работа с БД
- `sync_runner.py` — планировщик
- `.env` — секреты
- `data/vitro.db` — база данных

## Файлы, которые НЕ пушить
- `.env` — никогда
- `data/vitro.db` — никогда
- `COMMIT_MSG.txt` — создавать можно для `git commit -F`, но НИКОГДА не коммитить и не пушить

## Архитектурные правила
- `_load_all_categorized()` в `vitro/ui/deadlines.py` — единый источник истины. Не дублировать SQL.
- «Узкие места» не оптимизировать без явной просьбы: `_load_all_categorized`, `_load_waiting_review`, `_search_comments`, `_load_complex_table`.
- Кэш: `@st.cache_data(ttl=3600)` для загрузчиков, `ttl=600` для справочников. Никаких `st.cache_data.clear()` в кнопках «Обновить» (кроме `admin.py`).
- Все `st.plotly_chart` — с уникальным `key=`.
- Каскадные фильтры: Дисциплина → Раздел → Расположение → Комплект.

## Что можно менять свободно
- `vitro/ui/`
- `vitro/text_utils.py`
- `vitro/workdays.py`
- `scripts/`
