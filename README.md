# Vitro-tracker

Веб-приложение для управления замечаниями к рабочей документации (РД) из Витрокад.

**Проект:** АТП ТЛП (проектировщик)  
**Стек:** Python 3.14 · Streamlit 1.64 · SQLite · Plotly 7.1 · pandas 3.0 · openpyxl 3.1 · reportlab 5.0

## Что делает

- Синхронизирует замечания, листы и комплекты из SharePoint (Витрокад) в локальную БД SQLite (~35 МБ, ~66 000 замечаний).
- Позволяет специалистам категоризовать замечания (4 категории) с оптимистичной блокировкой.
- Даёт аналитику: Сводка по проекту (5 секций), динамика, авторы, сроки, категории, поиск, экспорт.
- Выгружает данные в Excel (форматированные отчёты) и PDF.

## Архитектура

### Единый источник истины

Все вкладки используют функцию **`vitro/ui/deadlines.py` → `_load_all_categorized()`** для получения активных замечаний. SQL не дублируется.

Функция возвращает колонки:
- `holder` — `ours` / `customer` / `customer_a` / `annulled`
- `our_status` — `new` / `in_work` / `rejected` / `discussion`
- `our_bucket` — `≤10` / `10–30` / `30–90` / `>90`
- `customer_bucket` — `≤10` / `10–30` / `30–90` / `>90`
- `category_flag` — старая логика (для совместимости)
- `status`, `doc_status`, `discipline`, `section`, `complex`, `sheet`

### Кэширование

- `@st.cache_data(ttl=3600, show_spinner=False)` — для загрузчиков данных
- `ttl=600` — для справочников (дисциплины, разделы, комплекты)
- **Никаких `st.cache_data.clear()`** в кнопках «Обновить» (кроме `admin.py`)

### Streamlit-специфика

- Все `st.plotly_chart` — с **уникальным `key=`** (иначе DuplicateElementId)
- Каскадные фильтры: Дисциплина → Раздел → **Расположение** → Комплект
- 4-й блок шифра: `complex.split("-")[3]` (`.upper()`)

## Терминология

| Техническое имя | Отображение в UI |
|----------------|------------------|
| `holder == "ours"` | АТП ТЛП |
| `fix_date` | Наш ответ |
| `our_bucket == "≤10"` | Срок ответа не превышен |
| `our_bucket > "≤10"` | Просрочено (>10 р.д.) |
| `holder == "customer"` | Заказчик (Выполнено) |
| `category_flag` | Категории (ручная разметка) |

## Известные проблемы

- **`history_summary`** — устаревшая логика («Выполнено» внутри «Закрыто»). Не синхронизирована со Сводкой.
- **`xlsx_builder.py`** — та же проблема (`_is_closed` объединяет «Закрыто» + «Выполнено»).
- **Планировщик Windows** — возможны пропуски в логах. Проверить настройки.
- **Вкладки / хедер** — не прилипают вместе с полосой даты.
