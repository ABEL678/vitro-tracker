# Vitro-tracker

Веб-приложение для управления замечаниями к рабочей документации (РД) из Витрокад.

**Проект:** АТП ТЛП (проектировщик)  
**Стек:** Python 3.14 · Streamlit 1.64 · SQLite · Plotly 7.1 · pandas 3.0 · openpyxl 3.1 · reportlab 5.0

## Что делает

- Синхронизирует замечания, листы и комплекты из SharePoint (Витрокад) в локальную БД SQLite (~35 МБ, ~66 000 замечаний).
- Позволяет специалистам категоризовать замечания (4 категории) с оптимистичной блокировкой.
- Даёт аналитику: Сводка по проекту (5 секций), динамика, авторы, сроки, категории, поиск, экспорт.
- Формирует **План выдачи комплектов** (вкладка «📅 План выдачи»): ведомости Excel → комплекты и чертежи, статусы, сроки готовности, бублики «всего/план», детальная таблица с выгрузкой за период.
- Выгружает данные в Excel (форматированные отчёты) и PDF.

## Архитектура

### Единый источник истины

Все вкладки используют функцию **`vitro/ui/deadlines.py` → `_load_all_categorized()`** для получения активных замечаний. SQL не дублируется.

### Единый источник истиины (листы)

**`vitro/sheets.py` → `unique_vitro_sheets(rows)`** — единственный источник уникальных листов. Дедуп ревизий: последняя по `(complex, leaf)` — `max(vitro_version)`, затем `max(id)`.

Функция возвращает колонки:
- `holder` — `ours` / `customer` / `customer_a` / `annulled`
- `our_status` — `new` / `in_work` / `rejected` / `discussion`
- `our_bucket` — `≤10` / `10–30` / `30–90` / `>90`
- `customer_bucket` — `≤10` / `10–30` / `30–90` / `>90`
- `category_flag` — старая логика (для совместимости)
- `status`, `doc_status`, `discipline`, `section`, `complex`, `sheet`

### Кэширование

- `@st.cache_data(ttl=3600, show_spinner=False)` — для загрузчиков данных
- `ttl=600` — для справочников (дисциплины, разделы, комплекты)
- **Никаких `st.cache_data.clear()`** в кнопках «Обновить» (кроме `admin.py`)

### Streamlit-специфика

- Все `st.plotly_chart` — с **уникальным `key=`** (иначе DuplicateElementId)
- Каскадные фильтры: Дисциплина → Раздел → **Расположение** → Комплект
- 4-й блок шифра: `complex.split("-")[3]` (`.upper()`)

#### Фильтры во всех вкладках (единый стандарт)

С версии 1.4 единый блок фильтров живёт в **`vitro/ui/_filters.py` → `render_standard_filters()`** и используется во всех вкладках (эталон — «Сводка по проекту»):

1. **Каскад (ряд 1):** Дисциплина → Раздел → Расположение → Комплект → Марка комплекта.
2. **Дополнительно (ряд 2):** Статус замечания + Статус листа (там, где применимы).
3. **3-й ряд:** вкладко-специфичные фильтры (Лист, Автор, Категория, Лимит, период и т. п.).

Справочники каскада — общие: `load_discipline_options`, `load_section_options`, `load_kit_options`; справочник «Расположение» — `BLOCK_OPTIONS` в `_filters.py`. Фильтрация DataFrame — `apply_df_filters()` (и `_filter_by_blocks` / `_filter_by_marka`, работающие и с колонкой `complex`, и с `Комплект`).

### Терминология

#### Технические имена → UI

| Техническое имя | Отображение в UI |
|----------------|------------------|
| `holder == "ours"` | АТП ТЛП |
| `fix_date` | Наш ответ |
| `our_bucket == "≤10"` | Срок ответа не превышен |
| `our_bucket > "≤10"` | Просрочено (>10 р.д.) |
| `holder == "customer"` | Заказчик (Выполнено) |
| Статус `Выполнено` | АТП ТЛП перевёл в «Выполнено» |
| Статус `Закрыто` | Закрыто заказчиком (формально) |
| `category_flag` | Категории (ручная разметка) |
| `status` (comments) | Статус замечания (сырой из Витрокад) |
| `doc_status` (comments) | Статус листа (сырой из Витрокад) |

#### Группы статусов листов

| Группа в UI | Сырые значения |
|-------------|----------------|
| Группа «A — утверждён» | Сырой статус листа `A` |
| Группа «B — к сдаче» | Сырой статус листа `B` |
| Группа «C — в работе» | Сырой статус листа `C` |
| Группа «И — информационный» | Сырой статус листа `И` |
| Группа «На согласовании Заказчика» | «ДЛЯ СОГЛАСОВАНИЯ» + «НА РАССМОТРЕНИИ» |
| Группа «Готовится к загрузке» | «НА КОРРЕКТИРОВКЕ» + «РАЗМЕЩЕНО» |
| Группа «Аннулировано» | Сырой статус листа `АННУЛИРОВАНО` |
| Группа «Прочее» | Все сырые, не попавшие в другие группы |

## Известные проблемы

- **`history_summary`** — устаревшая логика («Выполнено» внутри «Закрыто»). Не синхронизирована со Сводкой.
- **`xlsx_builder.py`** — та же проблема (`_is_closed` объединяет «Закрыто» + «Выполнено»).
- **Планировщик Windows** — возможны пропуски в логах. Проверить настройки.
- **Вкладки / хедер** — не прилипают вместе с полосой даты.

## План выдачи комплектов (вкладка «📅 План выдачи»)

- **Вводные данные (Excel):** «Ведомость основных комплектов» + «Ведомости чертежей каждого комплекта». Шаблоны скачиваются из вкладки; колонки распознаются по названиям заголовков.
- **Данные хранятся в SQLite:** таблицы `plan_kits` и `plan_drawings` (`vitro/sqlite_db.py`); парсеры/шаблоны/выгрузка — `vitro/plan_xlsx.py`.
- **Общая таблица:** шифр, наименование, дисциплина, раздел, общий статус («Загружен в Витро» / «Загружается (частично)» / «План (не загружен)» / «Только в Витро»), листов в Витро/план, **редактируемый срок готовности**.
- **Бублики:** «Комплектов всего/план» и «Листов всего/план» (по результату фильтрации).
- **Детальная таблица:** Дисциплина / Раздел / Комплект(ы) / Наименование / Кол-во чертежей (план) / Плановая дата / Статус комплекта — с фильтром по периоду (дата позиции = плановая дата чертежа, иначе срок готовности комплекта) и плашкой «📥 Выгрузить в Excel».

## Безопасность

- **`.env`** — НЕ в git (пароли, токены)
- **`data/vitro.db`** — НЕ в git (~35 МБ, ~66 000 замечаний)
- **TLS-проверка сертификата Витро** — включена по умолчанию (`VITRO_VERIFY_SSL=true`); отключать только временно во внутреннем контуре.
- **`showErrorDetails = false`** — traceback не показывается пользователям.
- **Опасные операции в «Управлении»** — пишутся в журнал (`admin_clear`).
- **`_utils.py` → `download_plotly`** — только для будущего Экспорта
