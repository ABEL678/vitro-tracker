ИНСТРУКЦИЯ: применение патчей к репозиторию vitro-tracker
==========================================================

Патчи подготовлены для версии c7cc156 («feat(summary): calculate Customer
Total...», ветка main/release-1.3). Применяются по порядку.

СПОСОБ 1 — через git (рекомендуется)
------------------------------------
1. Откройте командную строку в папке репозитория (рядом с app.py).
2. Создайте ветку и примените патчи по порядку:

   git checkout -b release/1.4-plan
   git apply --check patches/01-security.patch   (проверка, ошибок быть не должно)
   git apply patches/01-security.patch
   git apply --check patches/02-filters.patch
   git apply patches/02-filters.patch
   git apply --check patches/03-plan-tab.patch
   git apply patches/03-plan-tab.patch

3. Закоммитьте и отправьте:

   git add -A
   git commit -m "feat: v1.4 — безопасность, единые фильтры, вкладка «План выдачи»"
   git push origin release/1.4-plan

СПОСОБ 2 — копированием файлов (если git недоступен)
----------------------------------------------------
1. Скопируйте содержимое папки files/ поверх репозитория,
   СОХРАНЯЯ структуру папок:
     files\app.py                        ->  app.py
     files\README.md                     ->  README.md
     files\AGENTS.md                     ->  AGENTS.md
     files\.streamlit\config.toml        ->  .streamlit\config.toml
     files\vitro\...                     ->  vitro\...
2. Новые файлы: vitro\plan_xlsx.py и vitro\ui\plan.py — просто копируются.
3. Ничего удалять не нужно; .env и data\vitro.db не затрагиваются.

ПОСЛЕ ПРИМЕНЕНИЯ
----------------
1. Запустите приложение:  streamlit run app.py
2. Проверьте: вкладок стало 9 (появилась «📅 План выдачи»).
3. На каждой вкладке — expander «Фильтры» с каскадом
   Дисциплина → Раздел → Расположение → Комплект → Марка.
4. При первом запуске в БД автоматически создаются таблицы
   plan_kits и plan_drawings (миграция не требуется).
5. В .env при необходимости можно вернуть старое поведение TLS:
   VITRO_VERIFY_SSL=false (только для внутреннего контура!).

     правки замечаний) вместо устаревания раз в час;

     32 загрузчика переведены на версионный кэш; тёплый клик ≈ 0 мс;
   • vitro/ui/search.py — кэш результатов поиска (300 с);
   • vitro/ui/plan.py — детальная таблица: показ первых 2000 строк
     (полный объём в Excel);
   • vitro/plan_xlsx.py — Excel-выгрузка строится один раз на набор
     данных, а не на каждом реране;
   • vitro/sync.py — сброс кэшей после синка из приложения.

   Применение: git apply patches/06-performance.patch
   (на состояние после патчей 04 и 05). Либо скопировать файлы из
   files-06/ (plan.py там уже включает и патч 05).

ПАТЧ 04 — поверх ветки release/1.4-plan c коммитом Гигакода 94456dc
--------------------------------------------------------------------
04-plan-real-registers.patch — адаптация парсеров вкладки «План выдачи»
к РЕАЛЬНЫМ регистрам «Комплекты чертежей» (ОВ/АР/ВК). Применять ТОЛЬКО
поверх 94456dc (у кого ветка собрана из 01–03 — сначала сквош или
накат 01–03). Что чинит:
  1) крах приложения при старте: невалидная regex с диапазоном «А-Z»
     (кириллица+латиница) в plan_xlsx.py — re.error на импорте;
  2) «0 строк» на реальных файлах: len(cols) < 2 в _find_header_row
     считал только обязательные колонки;
  3) шапки комплектов «АТ-РД-ОВ1-С-00\nСистема отопления» (перевод
     строки вместо пробела) теперь распознаются, названия комплектов
     попадают в план;
  4) пустые строки-разделители внутри листа больше не обрывают разбор
     (раньше терялось до половины строк — ОВ 457 из 882);
  5) приложения без шифра (СО/ВР/П.01) наследуют комплект, метки
     «Приложение 1» больше не создают мусорных комплектов;
  6) латинские двойники («АТ-РД-ОВ2-C-00» ↔ «АТ-РД-ОВ2-С-00») не плодят
     дубли комплектов;
  7) добавлена колонка «Номер листа» (sheet_no): берётся из полного
     шифра листа, иначе из «Номер листа»; мягкая миграция БД;
  8) пустые значения ведомости больше не затирают сохранённые
     названия/статусы/сроки (NULLIF в upsert);
  9) KeyError «holder» на вкладке «Авторы» при пустой базе (гвард).

Применение:

ПАТЧ 07 — поверх ветки release/1.4-plan (патчи 04–06 + правки Гигакода)
------------------------------------------------------------------------
07-plan-save-donuts-parse.patch — три критических исправления вкладки
«План выдачи комплектов». Файлы: vitro/ui/plan.py, vitro/plan_xlsx.py.
vitro/sqlite_db.py НЕ меняется (всё нужное уже есть: колонка sheet_no
с мягкой миграцией из 04-го, индексы из 06-го).

1) БЕСКОНЕЧНОЕ ЗАЦИКЛИВАНИЕ при «Сохранить комплекты/чертежи в план»
   Корень: колонка «Срок готовности» при пустых датах имеет тип
   datetime64[ns] → пустые ячейки = pd.NaT, а «NaT != NaT» и
   «NaT != None» дают True. Автосохранение сроков находило фантомные
   различия на КАЖДОМ реране, перезаписывало БД и вызывало st.rerun()
   → вкладка моргала и зависала бесконечно; кнопки импорта лишь
   запускали первый реран цепочки.
   Исправление:
   • _norm_date_val(): None/NaT/date/Timestamp/строка → date|None,
     пустота равна пустоте — фантомные diff невозможны;
   • _save_due_dates(): защита от разной длины строк редактора и БД;
   • st.rerun() УБРАН из всех блоков сохранения (комплекты, чертежи,
     очистка, автосейв сроков). Вместо него — архитектура стейта:
       - блок сохранения ставит st.session_state["plan_data_just_saved"]=True
         и flash-сообщение «plan_flash» + st.toast;
       - в конце render() флаг СНИМАЕТСЯ (pop) и вызывается ЕДИНСТВЕННЫЙ
         контролируемый st.rerun() — цепочка всегда ровно 1, цикл
         невозможен по построению; данные перечитываются из БД;
       - flash показывается в начале render() после рерана.
   • парсеры ведомостей кэшируются по содержимому файла — повторный
     парсинг Excel на каждом реране устранён.

2) БИЗНЕС-ЛОГИКА БУБЛИКОВ (по всем ведомостям, без учёта фильтров)
   • «Комплектов всего» = число уникальных шифров plan_kits
     («Ведомость комплектов»); «загружено» = сколько из них есть в
     documents (Витро); «план» = разница;
   • «Листов всего (план)» = сумма ВСЕХ строк plan_drawings;
     «загружено» = Σ min(план, Витро); «план» = разница (не сумма);
   • НОВАЯ подпись под бубликом комплектов: «⚠️ Для N комплектов
     отсутствует Ведомость чертежей» (N = plan_kits без kit_code
     в plan_drawings);
   • сохранена подпись «ℹ️ …N лист(ов) сверх планового количества»;
   • математика вынесена в чистую функцию _donut_numbers() (тестопригодна),
     агрегаты считаются SQL GROUP BY с версионным кэшем — без выгрузки
     14k строк на каждом реране.

3) КОЛОНКИ «ДИСЦИПЛИНА», «РАЗДЕЛ», «НОМЕР ЛИСТА» НА РЕАЛЬНЫХ РЕГИСТРАХ
   В регистрах «Комплекты чертежей» (АР/ОВ/ВК) колонок «Дисциплина» и
   «Раздел» физически нет — поэтому были пустыми. Теперь они ВЫВОДЯТСЯ:
   • Дисциплина — буквенная часть 3-го блока шифра комплекта
     (АТ-РД-АР1-С-00 → «АР», ОВ2 → «ОВ», ТМ-С-П1 → «ТМ»); если колонка
     «Дисциплина» в файле есть — она имеет приоритет;
   • Раздел — имя листа книги («Подземная часть», «Надземная часть
     Корпус 1», подчёркивания → пробелы; служебные «Лист1»/«Sheet2»
     игнорируются); колонка «Раздел» в файле приоритетнее;
   • «Номер листа» — ключи расширены («номер листа», «№ листа»,
     «номер», «лист»); приоритет: полный шифр листа → колонка
     «Номер листа» (как и было); в детальной таблице и предпросмотре
     колонка больше не теряется при NULL в БД.
   То же выведение дисциплины добавлено в parse_kits_workbook.
