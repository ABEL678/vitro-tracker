ОТКУДА БРАЛИСЬ 632 КОМПЛЕКТА (вместо ~479 реальных)
---------------------------------------------------
В parse_kits_workbook шифр НЕ проверялся вообще: в план попадала ЛЮБАЯ
непустая ячейка колонки «Шифр». В реальной ведомости это:
  - строки-разделы: «Подземная часть», «Надземная часть Корпус 1»;
  - итоги: «Всего», «ИТОГО:»;
  - полные шифры ЛИСТОВ: «АТ-РД-АР1-С-00-1.1», «…-2.1.0»;
  - приложения: «Приложение СО», «П.01», «СО», «ВР»;
  - случайные даты/марки: «01.02.2026», «АР».
Проверка на реальном воспроизведении: 4 реальных комплекта + 10 строк
мусора → парсер возвращал 14 «комплектов» без единого предупреждения.
В масштабе ведомости: 479 + 153 мусорных = 632.

ИСПРАВЛЕНИЕ (plan_xlsx.py):
  - новая функция _kit_code_of(): нормализация + СТРОГАЯ регулярка;
  - регуляра ужесточена: после блока дисциплины максимум 2 хвостовых
    блока по 1-3 буквоцифры БЕЗ ТОЧЕК (точки — только в номерах листов);
    6-блочные шифры листов, разделы, итоги, приложения, даты не проходят;
  - все 69 реальных шифров ваших регистров АР/ВК/ОВ проходят (включая
    «АТ-РД-АР3-1-08Т» и «АТ-РД-ТМ-С-П1» — первая черновая версия
    регулярки их теряла, финальная — нет);
  - parse_drawings_workbook тоже переведён на _kit_code_of;
  - отброшенные строки СЧИТАЮТСЯ: предупреждение с числом и примерами
    («отброшено N строк(и) …: «Подземная часть»; «АТ-РД-АР1-С-00-1.1» …»).
    Отброс — это нормально, теперь он прозрачен.

ОТКУДА «ЛИШНИЕ» ЛИСТЫ ВИТРО (12 880 против 9 142 в ведомостях)
--------------------------------------------------------------
1. Дублей «PDF+DWG» НЕТ и не могло быть: sharepoint.py выгружает
   ТОЛЬКО PDF (фильтр substringof('.pdf', FileLeafRef)) — DWG в
   documents не попадает никогда.
2. Реальные источники превышения:
   а) комплекты, которых нет в ведомостях чертежей («Только в Витро»);
   б) НЕСКОЛЬКО PDF-строк ОДНОГО листа (повторные выгрузки/ревизии:
      COUNT(*) считал каждую строку как «лист»);
   в) PDF вне ведомостей (приложения, извещения).
3. ИСПРАВЛЕНИЕ (plan.py, _vitro_sheet_counts): COUNT(DISTINCT
   sheet_number) — уникальные листы комплекта; ревизии/копии одного
   листа = 1 лист. Комплекты, у всех файлов которых sheet_number пуст,
   считаются по файлам (иначе «исчезли» бы из Витро).
4. Честная арифметика бублика сохранена (патч 09): «Листов всего» =
   max(план, Витро). После дедупликации «в Витро» уменьшится до числа
   РЕАЛЬНЫХ листов — цифры сойдутся с фактическими листами, а не со
   строками выгрузки. Остаток честно показывается как «сверх плана».
   Примечание: «Сводка по проекту» продолжает считать строки
   (файлы) — её число может остаться выше; «листам» соответствует
   именно вкладка «План выдачи».

ПЕРЕСТАНОВКА БЛОКОВ И ПЕРЕИМЕНОВАНИЕ (plan.py)
----------------------------------------------
Новый порядок вкладки:
  Фильтры → Период «с/по» → 🎯 Бублики (подняты наверх, до таблиц) →
  📋 «Сводный план готовности комплектов и количества выданных
  листов» (переименованная сводная, группировка «Дисциплина → Раздел»,
  ИТОГО) → 🗓 Детальный план по листам комплекта → 📥 Кнопка выгрузки
  (перенесена в самый низ).

ПРОВЕРКА МЕХАНИКИ ПОДСЧЁТА (тесты, 44 проверки)
-----------------------------------------------
  - 2 PDF одного листа = 1 лист; статус «Загружается (частично)»
    считается по уникальным листам;
  - выдано + осталось = всего (без дублей и потерь);
  - комплекты: всего / в Витро / план — сходятся;
  - реальные регистры: 1989 строк листов, 69 комплектов, 0 мусора.
