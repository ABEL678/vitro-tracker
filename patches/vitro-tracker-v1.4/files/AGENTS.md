# AGENTS.md — Vitro-tracker

## Что это

Приложение для управления замечаниями к рабочей документации (РД).
Проект — АТП ТЛП (проектировщик). Заказчик выдаёт замечания к комплектам РД,
мы отвечаем и выпускаем новые ревизии.

## Стек

- Python 3.14
- Streamlit 1.64 (ленивая загрузка вкладок через radio)
- SQLite (`data/vitro.db`, ~35 МБ, ~68 000 замечаний)
- Plotly 7.1 (все графики — с `key=`, иначе DuplicateElementId)
- pandas 3.0, openpyxl 3.1, reportlab 5.0
- Git + приватный GitHub: https://github.com/ABEL678/vitro-tracker

## Архитектурные правила (ВАЖНО)

### 1. Единый источник истины

**`vitro/ui/deadlines.py` → `_load_all_categorized()`** — единственный источник активных замечаний.
**Не дублировать SQL.** Все вкладки используют эту функцию.

Она возвращает колонки:
- `holder` — `ours` / `customer` / `customer_a` / `annulled`
- `our_status` — `new` / `in_work` / `rejected` / `discussion`
- `our_bucket` — `≤10` / `10–30` / `30–90` / `>90`
- `customer_bucket` — `≤10` / `10–30` / `30–90` / `>90`
- `category_flag` — старая логика (для совместимости)
- `status`, `doc_status`, `discipline`, `section`, `complex`, `sheet`

### 2. Секции Сводки — формулы

- **Секция 3 (АТП ТЛП)**: `holder == "ours"`. 4 статуса = `new` + `in_work` + `rejected` + `discussion`.
- **Секция 4 (Заказчик)**: `holder == "customer"` + `customer_a` + `annulled`.
- **Секция 5 (Категории)**: только `holder == "ours"`.

### 3. Кэш

`@st.cache_data(ttl=3600, show_spinner=False)` — для загрузчиков.
`ttl=600` — для справочников (дисциплины, разделы, комплекты).
**Никаких `st.cache_data.clear()` в кнопках «Обновить»** (кроме `admin.py`).

### 4. Streamlit-специфика

- Все `st.plotly_chart` — с **уникальным `key=`**.
- Никаких `use_container_width` deprecated — использовать `width='stretch'` (когда перейдём).
- Каскадные фильтры: Дисциплина → Раздел → **Расположение** → Комплект.
- 4-й блок шифра: `complex.split("-")[3]` (`.upper()`).

#### Единый стандарт фильтров (с версии 1.4)

**`vitro/ui/_filters.py` → `render_standard_filters(key_prefix=...)`** — единый блок фильтров, эталон — «Сводка по проекту»:

- **Ряд 1 (каскад, 5 колонок):** Дисциплина → Раздел → Расположение → Комплект → Марка.
- **Ряд 2:** Статус замечания + Статус листа (флаги `show_remark_status` / `show_sheet_status`; у Поиска и Экспорта — расширенный список статусов через `remark_status_options`).
- **Ряд 3:** вкладко-специфичные фильтры через `extra_row()` (Автор, Категория, Лимит, период…).
- **Ряд 1, 6-я колонка:** через `row1_extra(col, kits)` (например, «Лист» в Сроках).
- Ключи виджетов = прежние префиксы вкладок (`sum_`, `dyn_`, `dl_`, `editor_`, `search_`, `exp_`, `authors_`, `wait_`, `ca_`, `plan_`) — выборки пользователей сохраняются.
- Справочники каскада — общие: `load_discipline_options`, `load_section_options`, `load_kit_options`; «Расположение» — `BLOCK_OPTIONS` там же.
- `_filter_by_blocks` / `_filter_by_marka` работают и с колонкой `complex`, и с `Комплект` (фикс бага марки в Поиске v1.3).

Во вкладках, где фильтры возвращают dict: `flt["disc"]`, `flt["section"]`, `flt["kits"]`, `flt["block_codes"]`, `flt["marka"]`, `flt["remark_statuses"]`, `flt["sheet_groups"]`, `flt["extra"]`.

#### Общие модули в vitro/ui/

- **`_filters.py`** — общие фильтры: статусы листов, статусы замечаний, марка комплекта.
  - `SHEET_GROUP_OPTIONS`, `REMARK_STATUS_OPTIONS`, `_SHEET_GROUP_TO_RAW`, `_ALL_KNOWN_RAW_STATUSES`.
  - Функции: `_doc_status_group`, `_sheet_groups_to_sql`, `_extract_2nd_block`, `_filter_by_marka`.

- **`_urls.py`** — `build_vitro_comment_url(vitro_guid, vitro_version, note_id)`.

- **`_auth.py`** — авторизация по требованию: `ask_user_name_dialog`, `ensure_user`.
  - Диалог ввода имени — ТОЛЬКО при сохранении (categories.py, authors.py).
  - Если отмена — сохранение прерывается.

#### Фильтр «Марка комплекта» (блок 2 шифра)

Во всех вкладках есть фильтр «Марка комплекта».
- Строгое совпадение 2-го блока шифра.
- `КЖ1` не найдёт `КЖ11`, `КЖ10`.
- В SQL — `LIKE '%-{marka}-%'`.
- В Python — `_filter_by_marka` (работает с `complex` и `Комплект`).

#### Вкладка «План выдачи» (с версии 1.4)

- Файлы: `vitro/ui/plan.py` (вкладка), `vitro/plan_xlsx.py` (шаблоны/парсеры/выгрузка), таблицы `plan_kits` + `plan_drawings` в `sqlite_db.py`.
- Данные общие для всех пользователей (SQLite), загрузка ведомостей — через `upsert_plan_kits` / `replace_plan_drawings_for_kits` (чертежи затронутых шифров заменяются целиком).
- Общая таблица: статус вычисляется («Загружен в Витро» / «Загружается (частично)» / «План (не загружен)» / «Только в Витро»), срок готовности редактируется в `st.data_editor` (автосохранение; диалог имени — только при нажатии кнопки).
- Каскад комплектов на План-вкладке объединяет справочник Витро и шифры из ведомостей (`kit_options_fn`).
- Фильтры — единый стандарт (`render_standard_filters`), дополнительно «Статус комплекта» и «Только позиции со сроками».

#### Ссылки на Витро

- В БД есть `documents.vitro_guid` и `documents.vitro_version`.
- Колонка «Витро» с `LinkColumn` в трёх местах: Авторы (drilldown), Сроки (список), Поиск (результаты).
- URL строится через `build_vitro_comment_url`.
- Активные замечания — подсветка, закрытые/аннулированные — без подсветки (OK).

#### Часовой пояс

- **Все timestamp в БД — UTC.**
- При показе — **МСК (+3)** через `vitro/time_utils.py` (`fmt_msk`).
- В хедерах — с пометкой «(МСК)».
- В логах и таблицах — без пометки.

#### Версия приложения

- В `vitro/config.py` — `APP_VERSION`.
- В футере app.py — отображается.

#### Авторизация

- Имя пользователя — в `st.session_state["user"]`.
- Диалог показывается через `ensure_user()` ТОЛЬКО при сохранении.
- Если пользователь отменил — `ensure_user()` возвращает `None`, сохранение прерывается.

### 5. Терминология в UI

- «мы» / «наше» → **«АТП ТЛП»**
- «fix_date» → **«Наш ответ»**
- Технические имена (`sync_runner`, `_load_all_categorized`) — **не показывать**
- «Хроника» → **«Просрочено заказчиком (>90 р.д.)»**
- «Учтено A/B» → **«Принято, но не закрыто»**
- «Заброшено» → **«Без движения >90 дней»**
