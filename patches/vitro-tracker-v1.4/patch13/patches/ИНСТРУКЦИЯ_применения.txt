ИНСТРУКЦИЯ: применение патчей к репозиторию vitro-tracker
==========================================================

Патчи подготовлены для версии c7cc156 («feat(summary): calculate Customer
Total...», ветка main/release-1.3). Применяются по порядку.

СПОСОБ 1 — через git (рекомендуется)
------------------------------------
1. Откройте командную строку в папке репозитория (рядом с app.py).
2. Создайте ветку и примените патчи по порядку:

   git checkout -b release/1.4-plan
   git apply --check patches/01-security.patch   (проверка, ошибок быть не должно)
   git apply patches/01-security.patch
   git apply --check patches/02-filters.patch
   git apply patches/02-filters.patch
   git apply --check patches/03-plan-tab.patch
   git apply patches/03-plan-tab.patch

3. Закоммитьте и отправьте:

   git add -A
   git commit -m "feat: v1.4 — безопасность, единые фильтры, вкладка «План выдачи»"
   git push origin release/1.4-plan

СПОСОБ 2 — копированием файлов (если git недоступен)
----------------------------------------------------
1. Скопируйте содержимое папки files/ поверх репозитория,
   СОХРАНЯЯ структуру папок:
     files\app.py                        ->  app.py
     files\README.md                     ->  README.md
     files\AGENTS.md                     ->  AGENTS.md
     files\.streamlit\config.toml        ->  .streamlit\config.toml
     files\vitro\...                     ->  vitro\...
2. Новые файлы: vitro\plan_xlsx.py и vitro\ui\plan.py — просто копируются.
3. Ничего удалять не нужно; .env и data\vitro.db не затрагиваются.

ПОСЛЕ ПРИМЕНЕНИЯ
----------------
1. Запустите приложение:  streamlit run app.py
2. Проверьте: вкладок стало 9 (появилась «📅 План выдачи»).
3. На каждой вкладке — expander «Фильтры» с каскадом
   Дисциплина → Раздел → Расположение → Комплект → Марка.
4. При первом запуске в БД автоматически создаются таблицы
   plan_kits и plan_drawings (миграция не требуется).
5. В .env при необходимости можно вернуть старое поведение TLS:
   VITRO_VERIFY_SSL=false (только для внутреннего контура!).

13-import-kits-and-sheets.patch — ПАТЧ 13 (текущий):
   vitro/ui/plan.py, vitro/plan_xlsx.py, vitro/sheets.py

   Фикс 1. Мусорные комплекты (бублик 541 -> 421):
     - vitro/plan_xlsx.py: публичная is_valid_kit_code() — единая
       точка проверки шифра.
     - vitro/ui/plan.py::_build_overview: шифры, не проходящие
       is_valid_kit_code, НЕ попадают в таблицу и бублик, даже если
       пришли из Витро («Только в Витро») или лежат в plan_kits со
       старых загрузок («АТ-РД-КЖ1,2-С-П2.3.ВР» и пр.).
     - vitro/ui/plan.py::_prune_plan_kits: невалидные шифры удаляются
       из plan_kits ВСЕГДА при пересохранении (и в режиме «Заменить
       план»), исторический мусор не выживает.

   Фикс 2. СМИК: листов 44, а не 33 — ПОЧЕМУ ТАК БЫЛО:
     Механизм «fallback по id» для файлов с пустым sheet_number был
     уже реализован в патче 12 и работает (тест: 33 файла с номерами
     + 11 файлов без номера = 44 уникальных листа). Реальная причина:
     синк пишет documents.complex «как есть» из имён папок SharePoint,
     поэтому один комплект мог храниться под НЕСКОЛЬКИМИ написаниями
     шифра — «АТ-РД-СМИК-0-00» и, например, «АТ-РД-СМИК-0-00 »
     (хвостовой пробел) или «AT-РД-СМИК-0-00» (латинские двойники).
     Группировка шла по сырому значению complex: у основного написания
     оставалось 33 листа, а 11 листов «уезжали» в фантомный вариант —
     он же раздувал «Комплектов всего» (541). Тот же эффект дают
     неразрывные пробелы (CHAR 160) в номере листа: SQL TRIM их не
     снимает, а pandas снимает — Сводка и План расходились.
     Что сделано:
     - vitro/sheets.py: sheet_key/dedup_document_rows нормализуют
       complex (trim + верхний регистр + латиница -> кириллица),
       варианты склеиваются и в Сводке (разрез «По комплектам»), и в
       Плане выдачи; sql_count_sheets перед TRIM заменяет CHAR(9)/
       CHAR(160) пробелом — SQL и pandas согласованы.
     - vitro/ui/plan.py::_vitro_sheet_counts: считает через
       sheets.dedup_document_rows — ТОТ ЖЕ код, что и Сводка
       (один стандарт на всё приложение).
     - vitro/ui/plan.py::_vitro_sheet_dates: ключи нормализуются —
       «Фактическая дата» находится и для листов из «кривых» папок.
     ЕСЛИ после патча СМИК всё ещё 33 — значит, у 11 файлов в БД
     пустой complex (NULL): лист не привязан ни к одному комплекту
     и не может быть атрибутирован автоматически. Диагностика:
       SELECT COUNT(*), SUM(sheet_number=''), SUM(complex IS NULL)
       FROM documents WHERE complex LIKE '%СМИК%';
       -- и посмотреть варианты написания:
       SELECT DISTINCT complex FROM documents WHERE complex LIKE '%СМИК%';
